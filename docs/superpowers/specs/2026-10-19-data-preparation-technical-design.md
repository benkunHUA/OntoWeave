- 日期：2026-10-19
- 状态：设计中（议题 1/7 已确定，下一议题：处理流程与派生版本的数据模型）
- 范围：P2「数据整理」的可视化处理、预览、构建、调度与来源追踪
- 输入：P1 同步生成的数据集版本（只读）
- 输出：新的派生数据集版本（不覆盖原始数据集）

## 1. 目标与边界

P2 要把「同步进来的原始数据集」整理成「可直接用于对象映射的派生数据集」：

`数据集版本 → 处理流程 → 预览 → 构建 → 派生数据集版本`

已确认边界：

- 处理流程只读取 P1 生成的数据集版本，不直接访问外部数据库。
- 输出新的派生数据集版本，不覆盖原始数据集。
- 数据集版本不可变；失败不改变当前版本。
- 每次构建都有运行记录，能区分成功、失败和无变化跳过。
- 沿用 Agent 对话 + 三栏工作台骨架，不另做一套菜单表单。
- 右侧操作通过结构化事件回流到中间对话，复用 `ConversationEvent`。

## 3. 议题一：MVP 处理算子范围

状态：已确定（2026-10-19）。

### 3.1 结论

MVP 只做 6 类处理算子，外加「数据源」和「输出」两个图节点：

| 类别 | 算子 | MVP 行为 |
|---|---|---|
| 行级 | 筛选 | 按列与常量比较过滤行，支持 AND/OR 组合 |
| 列级 | 选列 | 保留或删除字段，至少保留一个输出字段 |
| 列级 | 改名 | 修改输出字段名，要求非空且唯一 |
| 列级 | 改类型 | 显式转换为字符串、整数、小数、浮点、布尔、日期、时间戳 |
| 多表 | 合并 | 多路 `UNION ALL`，按位置对齐字段 |
| 多表 | 关联 | 两路等值关联，支持 `INNER JOIN` 和 `LEFT JOIN` |

「汇总」不进入 MVP；去重、排序、窗口、透视、派生字段、自定义 SQL/脚本也不进入 MVP。

### 3.2 算子边界

**筛选**

- 支持 `=`、`!=`、`>`、`>=`、`<`、`<=`、`IS NULL`、`IS NOT NULL`、`IN`。
- 支持 `AND` / `OR` 组合，可用括号表达分组。
- 只比较「字段与常量」；不做字段间比较、函数调用、子查询和正则。
- 空值语义按 SQL 三值逻辑执行，预览与构建使用同一套语义。

**选列**

- 输出输入字段的子集；至少保留一个字段。
- 只做列裁剪，不生成计算字段。

**改名**

- 只改输出字段名，不改数据。
- 输出字段名必须非空且在当前节点内唯一；只做大小写变化也视为改名。
- 改名不改变字段类型和下游引用。

**改类型**

- 第一版支持 `string`、`int`、`bigint`、`decimal`、`double`、`boolean`、`date`、`timestamp`。
- 显式转换，不做隐式推断；源类型与目标类型不兼容时在节点上直接报错。
- 转换失败按字段级错误处理，具体定位与展示在议题 3 确定。

**合并（Union All）**

- 支持两路及以上输入，全部按 `UNION ALL` 语义保留重复行。
- 输入字段数量和类型必须兼容，按位置对齐；不做按字段名自动匹配，不做类型自动提升。
- 输出字段名取第一路输入；需要不同名称时在下游「改名」处理。
- 不做去重（`UNION` / `UNION DISTINCT`），不做 schema 自动合并。

**关联（Join）**

- 只支持两路输入、等值关联键，支持 `INNER JOIN` 与 `LEFT JOIN`。
- 关联键可多列；不支持非等值条件、`FULL JOIN`、`RIGHT JOIN`、半连接和反连接。
- 一个关联节点只做一次两表关联；多表关联拆成多个节点。
- 不做关联基数校验；多对多会产生行放大，预览中必须能看出来（具体展示在议题 3）。
- 两侧同名字段在输出中自动加来源前缀；前缀规则在数据模型议题确定。

**数据源与输出**

- 数据源节点引用一个已发布的 P1 数据集版本；同一流程可引用多个数据集。
- 输出节点是流程的发布出口；一个流程可以有多个输出节点，每个输出生成一个派生数据集版本。
- 数据源与输出不承载计算逻辑。

### 3.3 为什么这样切

- 这 6 类算子覆盖了从原始数据到 P3 映射的最小闭环：裁剪字段、过滤无效行、统一命名与类型、补充关联信息、合并同构数据。
- 除「关联」外，其余算子都是单表行级或列级操作，预览成本低、结果确定，适合边改边看。
- 「汇总」会改变数据粒度，需要额外定义分组键、聚合函数、输出命名和空值语义；它对 P3 对象实例不是必需能力，先后置，避免 MVP 同时承担分析型语义。
- 去重、排序、窗口、透视和自定义 SQL 要么依赖更复杂的执行与权限模型，要么不是对象映射的前置条件，后续可以按真实需求追加，不会推翻当前图模型。

### 3.4 对后续议题的约束

- 数据模型必须能表达「多输入 DAG」：数据源、处理节点、输出节点，以及节点间的字段级 schema。
- 预览必须按节点执行，并能定位到「节点 + 字段」；关联后的行放大要能在预览中观察到。
- 构建必须整条流程原子成功或原子失败；任一节点失败不发布新版本。
- 前端提供算子面板和每个算子的配置表单，不提供自由 SQL 编辑器。
- P3 只消费输出节点生成的派生版本，不读取中间节点。

### 3.5 暂不纳入与触发条件

| 能力 | 处理 | 重新评估的触发条件 |
|---|---|---|
| 汇总（Group By + 聚合） | 后置 | P4 需要指标型对象，或真实流程无法用明细数据表达时 |
| 去重 | 后置 | 合并后出现明确的重复行治理需求 |
| 排序 | 后置 | 预览或输出需要稳定顺序时 |
| 窗口函数 | 后置 | 需要排名、累计、同比等计算时 |
| 透视 | 后置 | 出现明确的宽表转换需求 |
| 派生字段 / 表达式 | 后置 | 筛选、改名、改类型无法表达常见计算时 |
| 自定义 SQL / 脚本 | 后置 | 算子组合无法覆盖真实场景，且完成安全与沙箱设计后 |
