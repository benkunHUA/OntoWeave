# P3 变成对象

- 状态：✅ 已完成（2026-10-24 验收通过；性能 20 万行降级，端到端场景有条件覆盖）
- 目标：把整理好的数据集字段映射成对象属性和关系，生成可查询的对象实例与关系实例。
- 完成标准：能指定对象类型、唯一标识和显示名称；字段能映射到属性；能生成并查询对象实例和关系实例。

## 已确认约束

- 只消费已发布的数据集版本，不直接读取同步运行中的临时数据。
- 对象和关系进入现有本体共享池，复用已有对象类型、属性和关系定义。
- 生成过程必须有运行记录，失败不破坏已有实例。
- P3 第一版的对象类型必须先在现有本体建模中定义；P3 只负责选择已有对象类型并绑定数据集，不从数据集反向创建对象类型。
- P3 第一版采用一对一绑定：一个对象类型只绑定一个数据集，一个数据集也只能绑定一个对象类型。
- 字段映射按“一个属性最多一列、一列最多一个属性”处理；未映射的可选属性取空值，必填属性未映射或类型不兼容时阻止生成；不做静默类型转换。
- P3 第一版使用已有对象类型上的单属性 primary key / title key；主键必须非空、唯一、稳定，重复主键整批失败；标题为空时显示回退到主键。复合主键后置。
- 多对多关系纳入 P3 第一版：绑定已发布连接表数据集，两列分别映射两端主键；同一对象对去重；缺失目标跳过并告警；连接表其余列暂不作为关系属性。
- 对象映射和连接表映射只允许选择已发布、当前用户可见且存在当前版本的数据集；用户选择数据集身份而非历史版本，生成时使用当前已发布版本。
- P3 使用独立于 P1/P2 数据集的对象存储承载当前对象实例与关系实例；该存储不暴露为普通数据集，只通过对象类型查询。
- 数据集发布新版本后按对象类型整批重建对象集，成功后原子切换；失败继续保留上一版可查询对象。连接表关系按同样方式重建。
- 第一版对象查询包含：对象列表分页、主键/标题搜索、多条件组合筛选（条件之间为 AND，不做 OR 或嵌套）、对象详情和关系双向查看；不做全文搜索、聚合、保存视图和导出。
- 筛选操作符按属性类型收窄：文本支持等于/不等于/包含/判空，数值与日期时间支持比较和判空，布尔支持真/假，枚举支持等于/不等于；不做跨类型隐式转换。
- 映射保存不等于生效：首次点击“生成对象”并成功后才可查询；修改映射期间旧对象继续可查询，只有新映射重建成功后才切换。
- 映射错误按“阻止生成”和“告警跳过”区分；数据集字段删除、改名或改类型时映射进入待修复状态并暂停自动重建，旧对象继续可查询。
- 映射使用画布交互：对象类型映射为“对象类型属性 ↔ 数据集字段”；多对多关系映射为“关系两端主键端口 ↔ 连接表字段”；外键关系不单独绑定数据集，只展示由对象属性映射推导出的只读关系图。
- P3 Agent 作为映射助手：可建议映射、解释错误、运行校验与预览、直接修改可撤销的映射草稿；修改主键/标题键、首次生成、全量重建、解绑和修改连接表绑定必须确认；不创建对象类型/属性/关系，不直接改对象实例。
- 对象类型定义变化不自动破坏现有对象：新增可选属性不阻塞；新增必填、删除属性、修改类型或关系定义时映射进入待修复并暂停自动重建；修复成功前旧对象继续可查询。
- P3 第一版沿用现有所有者权限，不新增共享、只读成员、字段级或数据级权限；用户系统与细粒度权限后置。
- 生成前提供无副作用的映射预览：对象预览展示样例对象和校验错误；多对多关系预览展示关系对与跳过原因；预览使用映射草稿和数据集当前已发布版本，不代表已经生成。
- P3 只保留当前成功对象集与关系集，不保留可查询的历史对象快照；运行历史记录来源版本、时间、计数和错误，重建失败时继续使用上一次成功结果。
- 允许更换数据集：旧映射和旧对象保持可用，新数据集生成成功后再切换，失败则继续使用旧数据。解绑对象类型或多对多关系需明确确认；解绑后停止更新并删除对应对象/关系实例，但保留对象类型、关系定义和数据集。
- P3 新增独立“对象数据工作台”，不把实例映射塞进现有建模页；右侧固定三个标签页，标签内容随左侧选中的对象类型、外键关系或多对多关系切换。
- 索引任务不引入消息队列：数据库队列表是任务唯一事实来源，用 `FOR UPDATE SKIP LOCKED` 领取并配合租约、心跳和超时恢复；RabbitMQ 只做 Java 到 Python 的事件通知和可选唤醒，不承载任务状态。
- 前端只访问 Python `/api/v1`；Python 作为唯一 BFF，带服务 token 和 `ownerId` 调用 Java 的 `/internal/v1/ontology/...`。映射、生成、运行记录和对象查询全部经 Python 转发，Java 保持内网且不实现用户鉴权；Agent 工具直接复用同一批 Java 接口。
- 映射草稿使用 `revision` 乐观锁：保存和生成都带 `base_revision` / `mapping_revision`，版本不匹配返回 409 并附当前草稿；不自动合并、不 last-write-wins。生成时把映射 JSON 和 revision 冻结进索引版本，Agent 通过返回的 `previous_mapping` 支持单步撤销，不额外保存映射历史。
- 索引运行使用统一的 `ontology_index_run` 表，以 `subject_kind` 区分对象类型与多对多关系；每个绑定最多一条 `QUEUED` 和一条 `RUNNING`。新版本发布时原地更新排队的 `target_version_id` 实现合并，运行中的任务不打断，跑完后由最新排队版本再生成并切换。worker 用 `FOR UPDATE SKIP LOCKED` 领取并持有租约，定期续租；租约过期的 `RUNNING` 标为 `FAILED(WORKER_LOST)` 并清理该 run 的 stage 数据，版本指针不动。取消排队任务直接置 `CANCELLED`，取消运行中任务只写 `cancel_requested_at`，由 worker 分批检查后停止。
- 对象列表使用 offset 分页：`page` 从 1 开始，`page_size` 默认 20、最大 200，固定按 `primary_key_value` 升序，响应固定返回 `total`、`page`、`page_size` 和 `index_version_id`。不做版本钉住；前端发现 `index_version_id` 变化时提示“对象已更新”并回到第 1 页。
- 筛选使用派生值表：对象实例的 `properties` 只用于详情展示，另建 `object_instance_value`，每个非空属性一行并按文本、数值、时间、布尔分列存储；筛选索引全部静态，文本包含用 `pg_trgm`，多条件 AND 用多个 `EXISTS` 组合。派生值与实例同批写入、按索引版本整体删除。
- 关系实例只存关系类型、两端对象类型 ID 和主键值，不存对象行 ID；按 from 和 to 各建一个索引支撑双向查询。对象详情用 `direction=outgoing|incoming` 查询，关系实例页可按两端主键过滤；展示对端标题时 join 对端对象类型的当前版本。
- 索引版本切换后旧版本标 `retired_at`，延迟 5 分钟（可配）后分批清理：每批 5000 行，先删派生值和关系实例，再删实例，最后删版本行。清理失败只重试，不影响查询；生成失败只清该 run 的 stage 数据，切换失败整批回滚，版本指针不动。
- 绑定表分草稿与生效两组字段：草稿为 `draft_dataset_id`、`draft_mapping`、`revision`；生效为 `active_dataset_id`、`active_dataset_version_id`、`current_index_version_id`。只有生成成功的事务才更新生效字段和版本指针；失败或未生成时旧对象继续可查。绑定只有一个 `status`（`ACTIVE` / `UNBOUND`），生成中状态由 `ontology_index_run` 表达。解绑置 `UNBOUND`、清空当前版本并删除实例，保留草稿映射和运行记录。
- 运行状态 v1 用轮询：运行记录页和映射页在有 active run 时每 2 秒查询一次，终态停止；Agent 不在对话轮次内轮询，提交生成后立即结束本轮，用户从运行记录查看进度，需要解释失败时再调运行详情工具。RabbitMQ 事件只做提前唤醒，不作状态载体。
- Agent 工具沿用 P2 的读/写分组：读工具含数据集列表与 schema、本体定义、映射读取、建议、校验、预览、运行列表与详情；写工具为 `update_mapping`、`start_generation`、`rebind_dataset`、`unbind`、`cancel_index_run`。写工具统一带 `base_revision` / `mapping_revision`，冲突返回 409；主键/标题变更、生成、换源、解绑和取消均需 `interrupt` 确认，其余字段映射可直接写草稿。
- 测试与验收：功能端到端用 2 万行数据保证速度；性能验收用单对象类型 50 万行、8 个属性，测批大小 1k / 10k / 50k 的生成耗时、列表首屏 P95 和三条件筛选 P95。Java 用 Testcontainers PostgreSQL 覆盖领取、租约恢复、合并、事务切换、清理和筛选 SQL；Python 覆盖 BFF 错误映射与 Agent 确认路径；前端覆盖画布连线和筛选操作符。
- 关系重建范围：任一对象类型重建时，所有 `from` 或 `to` 指向它的关系都重建，避免目标对象增删后留下悬空关系。外键关系用对象实例的外键属性值匹配对端主键；多对多读取固定连接表 snapshot 后分别 join 两端版本；本轮重建的一端用 stage，未重建的一端用当前版本。缺失端跳过并计数，重复对用唯一索引加 `ON CONFLICT DO NOTHING` 去重。
- 数据集新版本触发的自动重建只使用生效快照：从 `current_index_version` 读取 `mapping_snapshot`，再解析同一生效数据集的当前已发布版本；草稿映射和草稿换源不参与自动重建，只有用户显式“生成”才使用草稿。映射处于待修复状态时暂停自动重建。

## 待讨论议题

1. ✅ 字段与属性的类型映射和校验规则。
2. ✅ 唯一标识、显示名称和重复数据的处理。
3. ✅ 关系实例的依据：外键 + 多对多连接表。
4. ✅ 数据集新版本生成后，对象实例采用按对象类型全量重建，成功后原子切换。
5. ✅ 对象实例的存储位置与查询接口。
6. ✅ 映射失败、字段缺失和类型不兼容如何展示给用户。
7. ✅ 对象映射和连接表映射可选择的数据集范围：数据集类型、发布状态、权限与可见性。
8. ✅ P3 的交互入口、Agent 职责和人工确认边界。
9. ✅ 映射、对象和关系的查看与编辑权限沿用所有者模型，细粒度权限后置。

| 2026-10-23 | 技术架构：映射并发控制 | 绑定表维护自增 `revision`；保存用 `WHERE revision=?` 乐观锁，冲突返回 409 和当前草稿；生成请求带 `mapping_revision` 并冻结映射快照；前端与 Agent 共用接口，撤销用 `previous_mapping` 回写。 |
| 2026-10-23 | 技术架构：索引运行生命周期 | 统一 `ontology_index_run`；每绑定最多一条排队和一条运行中任务；新版本原地合并排队任务，运行中不打断；`SKIP LOCKED` 领取 + 租约续期，租约过期标 `WORKER_LOST` 并清 stage；取消排队直接置 `CANCELLED`，运行中写 `cancel_requested_at` 分批退出。 |
| 2026-10-23 | 技术架构：列表分页 | offset 分页，`page` 从 1 起、默认 20 条、最大 200，固定按主键升序，始终返回 `total`；不钉旧版本，前端检测 `index_version_id` 变化后提示并回到第 1 页。 |
| 2026-10-23 | 技术架构：筛选存储 | 实例表 `properties` 只供展示；新增 `object_instance_value` 派生表按类型分列存值，静态 btree + `pg_trgm` 索引支撑等值、包含、范围和判空；AND 条件用多个 `EXISTS`；与实例同批写入，按版本删除。 |
| 2026-10-23 | 技术架构：关系查询 | 关系实例存关系类型、两端类型 ID 与主键值；from/to 各建索引；对象详情按 `direction=outgoing|incoming` 查询，关系实例页可按两端主键过滤；对端标题 join 当前对象版本，排序固定两端主键。 |
| 2026-10-23 | 技术架构：旧版本清理 | 切换后旧版本标 `retired_at`，延迟 5 分钟分批删除（5000 行/批），先删派生值与关系实例再删实例和版本行；清理失败只重试；生成失败清 run 的 stage，切换失败整批回滚且指针不动。 |
| 2026-10-23 | 技术架构：草稿与生效 | 绑定表同时存 `draft_*` 与 `active_*`；编辑只改草稿，生成成功事务才更新生效来源和当前索引版本；失败不动生效字段。`status` 仅 `ACTIVE` / `UNBOUND`；生成中由 run 表表达。解绑清空当前版本并删实例，保留草稿映射与运行记录。 |
| 2026-10-23 | 技术架构：状态推送 | 前端轮询运行状态（2 秒，终态停止）；Agent 不在轮次内等待生成结果，提交后即结束，需要解释失败时再查运行详情；RabbitMQ 事件仅提前唤醒，DB 为事实来源。 |
| 2026-10-23 | 技术架构：Agent 工具 | 读工具：数据集/字段、本体定义、映射、建议、校验、预览、运行记录；写工具：`update_mapping`、`start_generation`、`rebind_dataset`、`unbind`、`cancel_index_run`。写操作走 revision 乐观锁并复用 `interrupt` 确认；仅字段映射调整可直接写草稿。 |
| 2026-10-23 | 技术架构：测试与验收 | 功能 e2e 用 2 万行；性能验收用 50 万行 × 8 属性，测 1k/10k/50k 批大小的生成耗时、列表首屏 P95、三条件筛选 P95；Java 集成测试用 Testcontainers PostgreSQL 覆盖队列、切换、清理与筛选 SQL。 |
| 2026-10-23 | 技术架构：关系生成范围 | 对象类型重建时重建所有 from/to 指向它的关系；外键关系按属性值匹配对端主键，多对多读连接表 snapshot 后 join 两端；本轮重建端用 stage、另一端用当前版本；缺失端跳过计数，重复对 `ON CONFLICT DO NOTHING`。 |
| 2026-10-23 | 技术架构：自动重建来源 | 自动重建只用生效快照（`mapping_snapshot` + 生效数据集），忽略草稿映射与草稿换源；只有显式生成才使用草稿；映射待修复时暂停自动重建。 |
| 2026-10-23 | 实施拆分 | 1 份设计稿 + 9 份任务文档；W0 串行冻结契约，W1 四条 Java/Python 流并行，W2 前端外壳，W3 画布/数据/验收并行。采用单对话框编排子代理。 |
