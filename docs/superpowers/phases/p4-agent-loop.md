# P4 Agent 使用

- 状态：⏳ 未开始
- 目标：让 Agent 能查询对象和关系、选择动作、填写参数、请求人工确认、执行动作并回读结果，形成可验证的闭环。
- 完成标准：动作执行有前置校验和原子性；每次执行记录谁、何时、改了什么；Agent 能基于真实结果继续对话。

## 任务拆分

| 子任务 | 状态 | 说明 |
|---|---|---|
| 4.1 动作执行技术设计 | ⏳ 未开始 | 执行入口、参数装配、校验、事务与回滚 |
| 4.2 动作实例与审计 | ⏳ 未开始 | 执行记录、操作者、时间、变更前后值 |
| 4.3 Agent 查询工具 | ⏳ 未开始 | 查询对象、关系、动作定义和可用实例 |
| 4.4 Agent 动作工具 | ⏳ 未开始 | 选择动作、填写参数、请求确认 |
| 4.5 执行后验证 | ⏳ 未开始 | 重新查询并汇报实际结果；失败原因回传 |

## 已确认约束

- 动作只能通过已定义的动作类型、参数、规则和提交校验执行。
- 提交前必须校验；失败不能只改一半。
- 修改真实数据前需要人工确认。
- 每次执行留下审计记录。
- Agent 不直接拼 SQL 修改数据，只调用受控工具。

## 待讨论议题

1. 第一批支持哪些动作，以及执行入口和权限边界。
2. 校验失败、并发修改和部分失败如何处理。
3. 审计记录包含哪些字段，是否需要变更前后值。
4. Agent 能看到哪些对象和关系，查询结果如何裁剪。
5. 什么情况下必须人工确认，确认交互如何复用现有中断卡片。
6. 执行后如何验证并汇报实际结果。
